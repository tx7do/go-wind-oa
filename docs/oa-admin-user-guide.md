# GoWind OA 管理后台使用教程

本教程面向管理后台的日常使用者（审批人、人事/行政、流程管理员），按侧边栏菜单逐页讲清楚：每页能做什么、关键字段什么含义、常用操作怎么点。环境的启动与登录见 [快速上手](./oa-quick-start.md)。

菜单入口：侧边栏「**OA 工作流**」分组。

## 登录

登录页需要四样：租户编号、账号、密码、图形验证码。

- **租户编号**：平台超管留空；企业租户用户填本租户编码（演示环境是 `super`）。同一账号在不同租户下是隔离的，只能看到本租户的数据。
- 若账号开启了两步验证（MFA），密码校验通过后还会进入动态口令页，输入 Authenticator 上的 6 位数字完成登录。MFA 的开关在右上角头像 → 个人中心。

## 审批中心

「OA 工作流 → 审批中心」。顶部「**待我审批 / 已办**」切换：

- **待我审批**：当前轮到你的任务列表，点「审批」打开详情抽屉。
- **已办**：你处理过的历史任务。

详情抽屉从上到下四块信息：

1. **审批进度条**：流程走到哪一步、还有哪些节点。
2. **任务信息**：任务与节点标识。
3. **申请表单数据**：申请人填的内容，按字段键值展示。
4. **审批历史**：每一步的动作、时间、意见。

底部操作按钮（都可附带一条审批意见）：

| 按钮 | 作用 | 填什么 |
|------|------|--------|
| 通过 | 同意当前任务。会签（需全员通过）时你通过后流程等其他人；或签（一人通过即可）时流程立即推进 | 意见可选 |
| 驳回 | 不同意，整个申请立即变为「已驳回」 | 意见可选 |
| 转办 | 把这条任务转给别人办 | 弹窗里按姓名搜索选择对方 |
| 加签 | 在当前节点临时增加一个审批人，需要TA也处理后流程才继续 | 弹窗里按姓名搜索选择对方 |

> 列表右上角有分页控件；切换「待我审批 / 已办」时页码会重置。

## 流程定义

「OA 工作流 → 流程定义」。每种审批（请假、报销……）都由一条流程定义驱动，定义 = 节点图 + 申请表单描述。

### 列表页

列：名称/编码/版本/状态/创建时间。顶部可按**名称**搜索、按**状态**筛选。操作：

- **查看**：只读抽屉，看节点配置与表单 Schema 的 JSON。
- **启用 / 禁用**：切换状态（有确认框）。禁用后新的申请无法挂到该定义；进行中的实例不受影响。
- **导出**：把定义下载为 JSON 文件，用于备份或迁移到其他环境。
- **导入**：选择之前导出的 JSON 文件恢复定义。
- **新建**：进入定义编辑抽屉。

### 可视化编辑器（新建/编辑抽屉）

抽屉顶部有「**可视化 / JSON**」两种模式，随时互转；可视化模式改完会实时生成配置预览，提交前自动校验（每个审批节点至少要有一个审批人等）。

**画布**：节点可拖拽摆放，连线展示流转方向；条件分支的边上会显示条件表达式，点击连线可选中编辑。

**可添加的节点类型**：

| 节点 | 用途 |
|------|------|
| 开始 / 结束 | 流程的起点与终点 |
| 审批节点（TASK） | 真正需要人处理的节点 |
| 条件分支（EXCLUSIVE_GATEWAY） | 按条件走其中一条出边，如「天数 > 3 走总监审批」 |
| 并行分裂（FORK） | 同时开出多条并行审批线 |
| 并行汇聚（JOIN） | 等并行线都到达后合流 |
| 子流程（SUBPROCESS） | 挂接另一条流程定义（填「编码:版本」，如 `LEAVE:1`） |

**审批节点配置**：

- **审批人**：可加多个。类型三选一：
  - `USER`：指定用户 ID；
  - `LEADER`：申请人所在部门（主组织单元）的负责人；
  - `POSITION`：某职位的全部在职人员（自动展开成多人）。
- **审批策略**：
  - `会签（ALL）`：节点内审批人**全部通过**才进入下一节点，任何一人驳回即整体驳回；
  - `或签（ANY）`：**任一人通过**即推进并取消其余人的任务，全部驳回才驳回。
- 申请人自己出现在审批人里会自动跳过（视为同意）；整个节点的审批人都是申请人时，该节点自动通过并继续推进。


**条件分支配置**：每条出边填一个条件表达式，命中哪条走哪条；其中一条可标记为 `default` 兜底（所有条件都不中时走它）。

**表单 Schema**：描述申请人在移动端填什么字段。字段类型：`text`（单行文本）、`textarea`（多行文本）、`number`（数字）、`date`（日期）、`select`（下拉，需给选项）；可标记必填。表单 Schema 是 JSON 格式，可视化模式下有字段表格辅助编辑。

> 想直接手写 JSON 也行：切到 JSON 模式编辑 `node_config`，切回可视化模式会自动解析。格式示例与引擎细节见 [后端架构设计](./oa-workflow-design.md)。

## 审批委托

「OA 工作流 → 审批委托」。你要休假时把审批任务临时交给同事：

1. 「新建」→ 选择**委托人**（你）和**被委托人**（代理人）。
2. 保存后，分配给你的待办任务会自动转给被委托人处理。
3. 约束：一人只能有一名代理人，且不能委托给自己。列表支持分页，可随时删除委托。

## 考勤管理

「OA 工作流」分组下共 5 页：

| 页面 | 能做什么 |
|------|----------|
| 考勤记录 | 按工作日期（默认今天）查所有人的打卡记录：上班/下班时间、当日结果（正常/迟到/早退/缺勤/请假/待定）。点「执行当日结算」立即重算当天结果；「考勤设置」按钮跳转到设置页修改上/下班时间 |
| 考勤设置 | 全租户统一的上班、下班时间 |
| 节假日设置 | 维护节假日表：类型 `HOLIDAY`（放假，不结算考勤）或 `WORKDAY`（调休上班日，周末也按工作日结算）。法定节假日与调休都靠这张表，正式使用前务必维护 |
| 考勤地理围栏 | 打卡有效范围：名称 + 纬度 + 经度 + 半径（米）。移动端打卡会上报定位 |
| 考勤 Wi-Fi 指纹 | 办公场所 Wi-Fi 的 SSID / BSSID（MAC 地址），移动端打卡会尽量采集当前 Wi-Fi 信息 |

> 每天有定时任务自动结算前一日的考勤；手动「执行当日结算」用于补算或纠错。

## 请假管理

「OA 工作流」分组下共 3 页：

| 页面 | 能做什么 |
|------|----------|
| 请假类型配置 | 定义假种：代码（如 `ANNUAL` 年假、`SICK` 病假）+ 名称 + 备注。移动端提交请假时从这里下拉选择 |
| 假期额度授予 | 给「用户 × 假种 × 年度」分配总额度（天）。列表展示总额与已用，可按年度筛选 |
| 请假申请 | 全租户请假单只读列表：类型、起止时间、天数、事由、状态、关联流程实例；可按状态筛选（进行中/已通过/已驳回/已撤回） |

额度联动：请假申请**审批通过**后自动扣减额度（按半天 0.5 递进）；驳回、撤回不扣。申请人撤回中的申请状态会显示「已撤回」。

## 报销 / 出差 / 加班 / 用印 / 外出

五类单据的管理页结构相同：**只读列表 + 状态跟踪 + 按状态筛选**（提交动作在移动端）。

- **报销管理**：列表含事由、总额、状态；点「查看明细」打开抽屉，看每行费用明细（类别、金额、费用日期、说明、发票文件）。
- **出差 / 加班 / 用印 / 外出申请**：各含业务专属字段（目的地、补偿方式、印章类型、文件份数等），同样只读。

这些单据提交后会自动挂到对应编码的流程定义上（如 `BUSINESS_TRIP`），流程定义不存在时系统按默认模板（提交给申请人主管，会签）自动创建并启用；审批终态只回写单据状态，没有额度之类的副作用。

## 公告发布

「OA 工作流 → 公告发布」。填标题、内容，选**发布范围**：

- **全员**：发给本租户所有人；
- **按部门**：在组织架构树上勾选部门（勾选父节点即包含其下成员）。

点「**发布公告**」后按所选范围展开成站内信，接收方在移动端「通知」页能看到。

## 其他相关入口

- **组织架构与人员**：在「系统管理」等基座菜单维护（部门、职位、用户）。流程定义里的 `LEADER` 审批人取自部门负责人，`POSITION` 取自职位在职人员——先把组织数据配好，流程才能找到人。
- **站内信**：公告与审批通知都落在站内信域，管理后台可查发送记录。

## 常见问题

| 现象 | 说明 |
|------|------|
| 单据页面没有「提交」按钮 | 设计如此：提交入口在移动端，管理后台负责查看、审批与配置 |
| 看不到别人的租户数据 | 多租户隔离：每个账号只能看到自己租户的数据；平台超管也只能看到租户 0 的数据 |
| 禁用了流程定义还会影响进行中的申请吗 | 不会，只影响新申请的挂接 |
| 改了流程定义，老申请会按新流程走吗 | 不会。已经发起的实例按发起时的定义执行；新申请按当前启用版本走 |
| 转办 / 加签怎么选人 | 弹窗里按姓名或工号直接搜索选择，无需再查数字 ID |

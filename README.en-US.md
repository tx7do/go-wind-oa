# go-wind-oa｜OA Workflow Approval System

> **A lightweight, linear, state-machine-driven workflow approval engine — go-wind-oa**

go-wind-oa is an office automation (OA) workflow approval system comprising a lightweight workflow approval engine, an admin console, and a mobile client.

The backend is built on the Go microservice framework [go-kratos](https://go-kratos.dev/) and follows a core/admin/app three-service separation: core-service is a pure-gRPC backend owning the workflow engine and internal messaging, while admin-service / app-service are HTTP edge forwarders.

The admin frontend is Vue3 + Element-Plus; the mobile client is Flutter.

## Backend Architecture

Three-service separation, modeled after `go-wind-cms`'s core/admin/app pattern:

- **core-service**: Pure gRPC, owns ent repositories and the workflow engine implementation. Registers `WorkflowService` (`oa.service.v1`) + `InternalMessageService` (`internal_message.service.v1`) + Category/Recipient. Middleware chain `logging + ent` (core is the backend called by admin/app, no auth).
- **admin-service**: HTTP edge, exposes auth + internal messaging + workflow HTTP endpoints for the admin frontend. Each service method is a forwarder calling core-service via gRPC clients. Middleware chain `logging → auth+authz (whitelist) → ent`; auth must precede ent (inverted order makes ent fall back to SystemViewer, breaking tenant isolation).
- **app-service**: HTTP edge, exposes auth + workflow HTTP endpoints for the mobile client. Same forwarder pattern and middleware order.

Proto domain separation: core's `oa/service/v1/workflow.proto` is pure gRPC (HTTP annotations stripped); HTTP routing annotations live in `admin/service/v1/i_workflow.proto` and `app/service/v1/i_workflow.proto` wrapper protos, which reference `oa.service.v1` message types. Auth HTTP endpoints are defined in `admin/service/v1/i_authentication.proto` and `app/service/v1/i_authentication.proto`, referencing cms `authentication.service.v1` message types.

See `docs/oa-workflow-design.md` for details.

## Backend Build

Each service directory has a Makefile (`include ../../../app.mk`); `SERVICE_NAME` selects the buf openapi template:

```bash
cd backend/app/core/service && make ent wire api build   # core has no openapi (pure gRPC)
cd backend/app/admin/service && make openapi wire api build
cd backend/app/app/service && make openapi wire api build
```

`make ent` generates the ent ORM (`--feature privacy` must not be omitted; it is the prerequisite for the `TenantPrivacy` policy to take effect). `make api` generates Go proto stubs. `make openapi` selects `buf.admin.openapi.gen.yaml` / `buf.app.openapi.gen.yaml` per service (core skipped). `make wire` generates `wire_gen.go`.

## Admin Frontend

Vue3 + Vite + TypeScript + Element-Plus + Pinia. OA module code:

- `src/api/composables/oa.ts` — Vue Query hooks wrapping the generated `apiClient.workflowService`.
- `src/api/generated/admin/service/v1/index.ts` — generated by `backend/api/buf.admin.typescript.gen.yaml`.
- `src/pages/app/oa/definition/` — workflow definition list + Drawer form.
- `src/router/routes/modules/app/oa.ts` — frontend route module (accessMode=frontend, auto glob registration).

```bash
cd backend/api && buf generate --template buf.admin.typescript.gen.yaml   # generate TS client
cd frontend/admin && pnpm i && pnpm dev
```

## Mobile Client

Flutter + bloc + cached_query + dio. OA feature:

- `lib/src/features/oa/services/workflow_service.dart` — `BaseService` subclass calling the generated `apiClient.workflowService`.
- `lib/src/features/oa/pages/{task_list,task_detail,submit_apply,notifications,attendance,shell}/` — pages.
- `lib/generated/api/app/service/v1/index.dart` — generated by `backend/api/buf.flutter.oa.dart.gen.yaml` (mobile Dart client, contains `ApiClient.workflowService` + `authenticationService`).

```bash
cd backend/api && buf generate --template buf.flutter.oa.dart.gen.yaml   # generate Dart client
cd frontend/mobile && flutter run
```

> The development machine currently lacks the Flutter SDK (only the fvm shell). Run `fvm use <version>` locally before executing.
